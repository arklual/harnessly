# Своя документация

Страница /help и команда агентов `harnessly docs` читают две вещи: разделы, встроенные в harnessly, и **собственные
папки документации машины**. Положите в такую папку страницы своей команды (регламенты, как устроены ваши сервисы,
ваши договорённости), и они сразу появятся рядом со встроенными — без пересборки и перезапуска.

## Где папка

| Настройка | Папка |
| --- | --- |
| ничего не задано | `~/.harnessly/docs` (папка данных рантайма, `docs/`) |
| `HARNESSLY_DOCS_DIR=/srv/team-docs` | эта папка |
| `HARNESSLY_DOCS_DIR=/srv/team-docs:/srv/ops-docs` | несколько, через двоеточие, как `PATH`; `harnessly docs add` пишет в первую |

Задайте переменную в окружении рантайма (env-файл юнита systemd, контейнер, values Helm); рантайм передаёт её во
вкладки агентов, так что `harnessly docs add` пишет туда же, откуда читает страница. `harnessly docs path` печатает
папки.

## Что в ней лежит

```text
team-docs/
├── runbooks/                 отдельный раздел
│   ├── section.json          его название, для кого он, где стоит
│   ├── README.md             его первая страница ("overview")
│   ├── 01-deploy-api.md      номер задаёт порядок и отбрасывается из имени: "deploy-api"
│   ├── rollback.md
│   └── img/
│       └── pipeline.png      картинки рядом со страницами
├── start/                    id встроенного раздела: эти страницы добавятся в него
│   └── vpn.md
├── onboarding/               папка без section.json — тоже раздел, по названию первой страницы
│   └── README.md
├── Team notes.md             Markdown-файлы в корне составляют раздел "team"
└── ru/                       русские переводы, те же пути: ru/runbooks/rollback.md
```

### section.json

```json
{
  "title": { "en": "Runbooks", "ru": "Регламенты" },
  "audience": "all",
  "order": 20,
  "pages": ["README.md", "01-deploy-api.md", "rollback.md"]
}
```

| Поле | Что значит |
| --- | --- |
| `title` | название раздела по языкам; английское — запасное |
| `audience` | `people`, `agents` или `all`: для кого написан; `harnessly docs` помечает это для агентов |
| `order` | место раздела; у встроенных 10 (начало работы), 40 (агенты), 50 (архитектура), 60 (свой сервер), 70 (приложения). Без него — после них |
| `pages` | необязательно: страницы по порядку. Без него — README первым, затем все `*.md` по имени файла |

### Дополнить или заменить встроенный раздел

Папка с именем встроенного раздела (`start`, `agents`, `inside`, `self-host`, `build-apps`) добавляет в него свои
страницы. Страница с тем же именем, что встроенная, **заменяет её на этой машине**: напишите свой `start/README.md`,
чтобы встречать команду своей первой страницей. `section.json` в такой папке может поменять и название раздела.

## Страницы, картинки, схемы

- Страница — Markdown; первый заголовок `#` — её название, заголовки `##` и `###` — оглавление.
- Картинки: png, jpg, gif, webp или svg до 8 МБ, по пути относительно страницы: `![Пайплайн](img/pipeline.png)`.
  Картинки с других сайтов не загружаются. Перевод без своей картинки показывает картинку английской страницы.
- Схемы: блок с пометкой `mermaid` рисуется, как в чате:

  ````markdown
  ```mermaid
  flowchart LR
      main --> ci["CI собирает образ"] --> deploy["deploy/prod"]
  ```
  ````

- Ссылки на другие страницы — по их файлам, относительно: `[откат](rollback.md)`, `[сейф](../safe.md)`. Они
  открываются внутри документации. Сырой HTML не показывается.

## Держите её в git

Папка — обычные файлы, поэтому привычный путь — репозиторий документации команды, склонированный в неё и
подтягиваемый по таймеру:

```bash
git clone git@git.example.com:team/docs.git /srv/team-docs
# таймер systemd или cron, каждые 10 минут:
git -C /srv/team-docs pull --ff-only --quiet
```

Тогда на всех машинах команды одни и те же страницы, а мерж в репозиторий документации — это и есть выкат.

## Пусть пишут агенты

Агент добавляет страницу командой `harnessly docs add` (см. [документацию из командной строки](../agents/docs.md)).
Попросите в чате: «запиши регламент того, что мы сейчас сделали для восстановления базы, с командами и скриншотом
результата». Страница ляжет в первую папку; если папка в git, закоммитьте её как любое другое изменение.
