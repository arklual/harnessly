# От нуля до работающего вида за 5 минут

Нужны `harnessly` на этой машине и открытый чат в Harnessly. Больше ничего: первому виду сборщик не нужен.

## 1. Создайте

```sh
harnessly app new acme.hello --template pane-chat
cd hello
harnessly app validate . --strict
```

`new` пишет папку, которая проходит `validate` как есть. `--strict` считает ошибкой и предупреждения: хорошая привычка с первой минуты.
Вид уже выглядит как Harnessly: он подключает `/__hl/hl-ui.css` (цвета платформы и классы `.hl-*`), поэтому светлая и тёмная темы
следуют за панелью.

```text
hello/
  harnessly/app.json     # манифест: id, цели, права, вид
  ui/index.html          # страница вида
  ui/main.js             # подключается к хосту; показывает загрузку и ошибку на странице
  ui/style.css           # ваш
  instructions.md, skills/…   # что получает агент (можно оставить как есть)
```

## 2. Поставьте саму папку и включите

```sh
harnessly app dev .
harnessly app enable acme.hello       # в чате этой вкладки
```

`dev` ставит папку, а не копию: правка доходит сразу. Файлы вида читаются заново при каждом открытии. Изменённый манифест,
`instructions.md` или `.mcp.json` прочтёт агент, который запустится после правки.

## 3. Откройте

Правая панель: «+», затем приложение. Или `harnessly open app:acme.hello`. Вы увидите заголовок, где показан вид, и кнопку, которая
пишет в чат. У страницы три состояния, и `main.js` обрабатывает каждое: скелет, пока идёт подключение, сама страница, и ошибка с кодом,
если хост не отвечает. Откройте `ui/index.html` как обычный файл, и получите именно ошибку: хоста нет.

Если вид остался пустым, посмотрите консоль панели (переключатель «Отладка» на странице приложения); `harnessly app explain acme.hello`
скажет, почему приложение выключено.

## 4. Измените что-нибудь

Поменяйте текст в `show(…)` в `ui/main.js` и откройте вид заново. Вызовите другой метод `hl` (`hl.storage`, `hl.files`; весь список —
`harnessly app catalog`) и проверьте ответ через `hl.refused(answer)`: протокол 2 отвечает на отказ объектом
`{ error, code, message }` и не бросает исключение, так что один `if` покрывает «здесь нельзя», «хост не умеет» и «не вышло».

## Рецепт: Vite + React + TypeScript

```sh
harnessly app new acme.board --template vite
cd board
npm install
npm run build        # собирает src/ в ui/
harnessly app dev .
harnessly app enable acme.board
```

`npm run dev` пересобирает при каждом сохранении; откройте вид заново, чтобы увидеть сборку. Шаблон минимален намеренно:

- `index.html` (исходник) подключает SDK обычным скриптом, а `src/main.tsx` модулем; `vite build` пишет результат в **`ui/`**: оттуда
  раздаётся вид.
- **Работает благодаря `base: './'` в `vite.config.ts`.** Вид раздаётся с сессией в адресе (`/<сессия>/<приложение>/ui/index.html`),
  поэтому каждый адрес в сборке должен быть относительным странице. Адрес от корня (`/assets/app.js`) теряет сессию, и файл
  отвечает 401. `validate` предупреждает, если находит такой в `ui/`.
- Модули, `fetch` собственных файлов вида и шрифты работают с хоста 0.16.198: файлы раздаются с сессией в пути и отвечают CORS
  непрозрачному origin фрейма. Раньше грузились только классические скрипты.
- Типы `window.harnessly` лежат в `src/app-sdk.d.ts` (копия `/__hl/app-sdk.d.ts`). Пакет `@harnessly/app-sdk` содержит те же типы
  и ES-модуль для сборщика, который его импортирует: `import { connect } from '@harnessly/app-sdk'`. В npm его нет: он лежит
  в [репозитории](https://github.com/ly-solutions/harnessly) (`internal/apps/sdk`); `scripts/app-sdk-package.sh` собирает его
  в `dist/app-sdk-npm`, а `npm install <путь>/dist/app-sdk-npm` подключает к приложению.
- Без `network` в манифесте из вида ничего не уходит (`fetch` на внешний адрес отклонён, см. [Бэкенд](03-backend.md)). Раздаётся
  только то, что в `ui/`: исходники держите в `src/`, снаружи.
