# Существующий сайт: агент управляет вашей админкой

У вас уже есть админка (Angular, React, что угодно), и вы хотите, чтобы агент чата работал в ней: читал, что в форме,
заполнял её, нажимал «Сохранить». Не глядя на экран и не кликая: админка сама сообщает агенту своё состояние и действия
короткими хуками в своём коде, а агент читает и пишет **модель формы** одним структурным вызовом. Все проверки, которые
действуют на человека, действуют и на агента: он пишет через ту же модель и сохраняет той же функцией.

Три примитива, все на `window.harnessly`, вне Harnessly все ничего не делают:

| Примитив | Что задаёт автор | Что получает агент |
| --- | --- | --- |
| `state(name, options)` | описание, схема, `get`, `set` | значение в контексте хода и тул `<name>_set` |
| `action(name, options)` | описание, схема аргументов, `run`, `mutates` | тул `<name>` |
| `screen(options)` | название, маршрут, подсказка | «человек на экране X» и что здесь делать |

## Пакет

Админка показывается окном по своему адресу. Пакет — это манифест и инструкции, больше ничего:

```json
{
  "id": "acme.admin",
  "name": "Acme admin",
  "version": "1.0.0",
  "targets": ["pane"],
  "permissions": ["tools.page", "context.publish"],
  "network": { "frames": ["admin.acme.example"] },
  "views": [{ "id": "main", "title": "Admin", "entry": "https://admin.acme.example/", "targets": ["pane"] }]
}
```

Админка должна разрешить Harnessly показывать себя во фрейме (`Content-Security-Policy: frame-ancestors` с адресом
вашего Harnessly). Её куки входа во фрейме считаются сторонними: первым делом проверьте вход в Safari.

## Загрузчик

Одна инлайн-строка в `<head>` шелла админки, до скриптов фреймворка:

```html
<script>(function(w,d,b,h){var m=w.parent!==w&&/(?:^#|&)hl-nonce=([\w-]+)/.exec(location.hash),q=m?[]:null,f=function(k){return function(){var c={k:k,a:arguments};q&&q.push(c);return{unregister:function(){c.off=1;c.h&&c.h.unregister()},refresh:function(){c.h&&c.h.refresh()},clear:function(){c.off=1;c.h&&c.h.clear()}}}};w.harnessly={q:q,hosts:h,nonce:m&&m[1],state:f('state'),action:f('action'),screen:f('screen')};if(m){var s=d.createElement('script');s.src=b+'/loader.js';d.head.appendChild(s)}})(window,document,'https://HARNESSLY_VIEWS/__hl/v1',['https://HARNESSLY_HOST']);</script>
```

Что она делает:

- **Вне Harnessly** (страница не во фрейме или в адресе нет `#hl-nonce=…`, который хост добавляет, открывая окно) она
  ничего не грузит. `window.harnessly` — заглушка: `state`, `action` и `screen` возвращают handle с пустыми методами.
  Код админки не проверяет, где он запущен, а обычный пользователь не скачивает ни байта.
- **Внутри** она грузит `loader.js` из папки, названной в строке; загрузчик берёт из той же папки `bridge-shim.js` и
  `app-sdk.classic.js`, проигрывает вызовы, сделанные админкой за это время, и подключается. Вызовы до загрузки SDK
  сохраняются по порядку; handle, который за это время сняли, не проигрывается.

Замените `https://HARNESSLY_VIEWS/__hl/v1` на папку, где лежат файлы. Два способа:

- **Своя копия** (работает везде): `harnessly app sdk ./public/hl` пишет `loader.js`, `bridge-shim.js`,
  `app-sdk.classic.js`, `loader-inline.js` и типы; в строке — `https://admin.acme.example/hl`. Повторяйте команду при
  обновлении Harnessly.
- **Сервер окон вашего Harnessly**: он раздаёт те же файлы по `/__hl/v1/`. `v1` — мажорная версия контракта SDK:
  обновление Harnessly не ломает админку, которая назвала `v1`.

Адрес пишете вы в самой строке, он никогда не берётся из адреса страницы: фрагмент говорит только «внутри», назвать
источник скрипта он не может. Если у админки есть CSP, разрешите эту папку в `script-src`.

**Кому админка доверяет.** Замените `https://HARNESSLY_HOST` в конце строки на адрес (origin) страницы вашего Harnessly;
адресов может быть несколько. Фрагмент в адресе — не доказательство: его может написать любая страница, которая возьмёт
админку во фрейм. Поэтому загрузчик пропускает рукопожатие только от названных адресов, и чужая страница не прочитает
ни одного состояния и не вызовет ни одного тула сессией вашего пользователя. Без этого списка загрузчик ничего не
грузит. `frame-ancestors` оставьте тоже: это вторая линия.

Нонс сразу убирается из адреса. У полной перезагрузки фрейма нонса нет, поэтому страница «снаружи», пока окно не
откроют заново; переходы внутри одностраничного приложения связь сохраняют.

## Состояние

```js
const handle = window.harnessly.state('event', {
  description: 'Форма нового мероприятия.',
  schema: { type: 'object', properties: { title: { type: 'string' }, price: { type: 'number', minimum: 0 } } },
  get: () => form.getRawValue(),
  set: (patch) => { form.patchValue(patch); return errorsOf(form); },
  subscribe: (changed) => form.valueChanges.subscribe(changed),
  rules: [{ id: 'title-case', text: 'Название без капса.', examples: { pass: ['Вечер джаза'], fail: ['ВЕЧЕР ДЖАЗА'] } }],
  check: (value) => (value.discount > 30 ? [{ field: 'discount', level: 'warn', message: 'Скидка выше обычной, скажи об этом человеку.' }] : []),
});
// когда компонент уничтожается:
handle.unregister();
```

- **Тул `event_set` принимает патч**: только изменяемые поля. SDK зовёт `set(patch)`, затем `get()` и отдаёт итоговое
  значение со всеми замечаниями разом.
- **`set` возвращает замечания формы**: массив, `{ issues }` или исключение. Все, а не первое.
- **`check(value)`** — правила кодом, только для вызовов агента; их замечания приходят с `source: "rule"`. Выполняется
  после `set`: значение уже в форме, человек его видит.
- **`rules`** — правила словами. SDK кладёт их в контекст и в описание тула, чтобы агент знал их до вызова. Судьи по
  ним пока нет.
- **Значение перепубликуется само**: с `subscribe` — через 300 мс после последнего изменения, без него — после каждого
  `set` и по `handle.refresh()`. Агент видит его на следующем ходу.
- Подтверждения нет: состояние только заполняет форму. Данные меняет действие.

## Действие

```js
window.harnessly.action('event_save', {
  description: 'Сохранить мероприятие.',
  mutates: true,
  run: async () => {
    const saved = await api.saveEvent(form.getRawValue());   // та же функция, что у кнопки
    return { id: saved.id };
  },
});
```

- **`mutates`** равно true, пока вы не написали `false`, и меняющее действие спрашивает человека перед каждым вызовом
  (`confirm: true`). `confirm: false` снимает вопрос у одного действия; `mutates: false` — для действия, которое только
  читает или что-то открывает.
- **`ok: true` только когда `run` завершился.** Исключение или замечание уровня `error` — это `ok: false`. Исключение
  становится замечанием с `source: "server"`; бросьте `{ issues: [...] }` или верните `{ issues }`, чтобы сказать
  `form` и назвать поля.
- `run` может вернуть `{ result, issues }`, чтобы передать предупреждения вместе с результатом.
- **`check(args)`** выполняется до `run`; ошибка останавливает действие, `run` не вызывается.

## Экран

```js
const screen = window.harnessly.screen({ title: 'Новое мероприятие', route: '/events/new', prompt: 'Здесь создают мероприятие; сначала уточни дату и площадку.' });
// уходя с экрана:
screen.clear();
```

Действует последний вызов; `clear()` экрана, который уже заменили, ничего не делает. Смена экрана хода агенту не даёт:
контекст меняется молча.

## Формат ответа и замечаний

Любой тул состояния или действия отвечает в одном формате:

```json
{
  "ok": false,
  "value": { "title": "КОНЦЕРТ", "price": -5 },
  "issues": [
    { "source": "form", "field": "price", "level": "error", "message": "Цена не может быть отрицательной" },
    { "source": "rule", "field": "title", "level": "error", "message": "Название без капса", "rule": "title-case" },
    { "source": "rule", "field": "discount", "level": "warn", "message": "Скидка выше обычной, скажи об этом человеку" }
  ]
}
```

| Поле | Что |
| --- | --- |
| `ok` | false, пока есть замечание уровня `error` |
| `value` (состояние) / `result` (действие) | состояние после патча; ответ `run`, `null`, если он не завершился |
| `issues[].source` | `form` (проверки самой формы), `rule` (правило для агента), `server` (отказ бэкенда) |
| `issues[].field` | поле, `""` для значения целиком |
| `issues[].level` | `error` блокирует; `warn` нет, и агент говорит о нём человеку |
| `issues[].message` | те же слова, что человек видит под полем |
| `issues[].rule` | id правила, для `source: "rule"` |

Чего в замечании нет, заполняет SDK: `level` — `error`, `field` — `""`, `source` — `form` для `set`, `server` для `run`
и всегда `rule` для `check`. Строка — это замечание с таким текстом.

## Контекст окна

Окно с состоянием или экраном публикует один документ (право `context.publish`):

```json
{
  "screen": { "title": "Новое мероприятие", "route": "/events/new", "prompt": "…" },
  "states": { "event": { "description": "…", "schema": {}, "value": { "title": "" }, "rules": [] } },
  "data": { "anything": "то, что окно передало в hl.publish" }
}
```

`hl.publish(data)` продолжает работать рядом: ваши данные попадают под ключ `data`. Окно без состояний и экрана
публикует свои данные как раньше. Весь документ — не больше 64 КиБ: публикуйте то, что нужно агенту, а не таблицу на
тысячу строк.

## Обёртки

Два примера, которые можно скопировать в общий пакет вашего шелла (по 15–20 строк, не считая импортов):

- Angular: [`exposeForm(name, formGroup, options)`](../../apps/examples/angular-expose-form.ts) читает `getRawValue()`,
  пишет `patchValue()`, превращает ошибки контролов в замечания и снимает состояние через `DestroyRef`.
- React с react-hook-form: [`useAgentForm(name, form, options)`](../../apps/examples/react-use-agent-form.ts) читает
  `getValues()`, пишет `reset()`, превращает `formState.errors` в замечания и снимает состояние в cleanup эффекта.

```ts
// Angular, в компоненте формы
exposeForm('event', this.form, { description: 'Форма нового мероприятия.', schema: eventSchema });
exposeAction('event_save', { description: 'Сохранить мероприятие.', mutates: true, run: () => this.save() });
```

```tsx
// React
useAgentForm('event', form, { description: 'Форма нового мероприятия.', schema: eventSchema });
useAgentAction('event_save', { description: 'Сохранить мероприятие.', mutates: true, run: save });
```

В микрофронтах строка загрузчика живёт в шелле один раз; ремоут вызывает обёртки и сам ничего не подключает.

## Ограничения

- 32 тула на окно (состояние — один, действие — один), схема тула 16 КиБ, описание 1000 символов (правила словами
  входят в него), ответ 256 КиБ.
- Имя — латинские буквы, цифры, `_`, `.`, `-`, не длиннее 59 символов, начинается с буквы.
- Окно, написанное для Harnessly с нуля, пользуется теми же тремя: `hl.state`, `hl.action`, `hl.screen` после `connect()`.
