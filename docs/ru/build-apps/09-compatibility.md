# Совместимость: приложение, которое переживёт обновления

Приложение, которое работало вчера, работает и после любого обновления harnessly — без правок автора. Здесь — что
обещает хост и что делает приложение (или агент, который его пишет), чтобы так и было.

## Что стабильно

- **SDK только растёт.** Метод, событие, поле контекста и право не удаляются и не меняют смысл. Нужно иначе — новое
  имя рядом, старое продолжает работать.
- **Устаревшее работает.** Устаревший метод выполняется; инспектор приложения пишет «устарело, вместо него …».
  Убрать его может только новая основная версия протокола, которую приложение выбирает само.
- **Права не отзываются задним числом.** Установка сохраняет выданные права. Новое право приходит только с новой
  версией приложения и кликом человека на экране установки.

## Объявите диапазон harnessly

`harnessly` в `app.json` — диапазон версий хоста, под которые написано приложение:

```json
{ "harnessly": ">=0.16" }
```

Хост вне диапазона приложение не запускает и говорит почему («нужна другая версия harnessly»). Указывайте самую
раннюю версию, где есть то, чем вы пользуетесь; верх оставляйте открытым.

## Спрашивайте, умеет ли хост, а не какая у него версия

```js
const hl = await harnessly.connect();
if (hl.has('files.read')) {
  const text = await hl.files.read('README.md');
}
```

`hl.has(имя)` — true, если хост делает этот метод здесь и у приложения есть право на него. Принимает имена SDK
(`files.read`, `storage.user.get`, `chat.send`) или имя метода моста (`harnessly/notify`). На старом хосте новый метод
просто false — приложение работает без него.

## Обрабатывайте отказ

Вызову отказывают, когда у приложения нет права, место его не разрешает или хост этого не умеет. Два способа:

- **Протокол 1 (по умолчанию).** Вызов отклоняется с `HarnesslyError`, причина — в `error.code`. Ловите:

  ```js
  try {
    await hl.chat.send('Готово');
  } catch (e) {
    if (e.code === 'permission_denied') showHint();
  }
  ```

- **Протокол 2.** Попросите его при рукопожатии — и любой метод отвечает на отказ значением, а не исключением:

  ```js
  const hl = await harnessly.connect({ protocol: 2 });
  const answer = await hl.chat.read({ last: 10 });
  if (hl.refused(answer)) {
    // answer.error: 'denied' (нет права, здесь нельзя), 'unsupported' (хост этого не умеет) или 'failed'
    return;
  }
  ```

Хост говорит на всех протоколах, на которых когда-либо говорил, поэтому приложение работает, какой бы оно ни назвало.
`hl.protocol` — тот, на котором хост говорит с окном (1 на хосте, который не знает 2).

## Устаревшее → замена

| Устарело | Вместо |
| --- | --- |
| `hl.flow.status()`, `hl.flow.go()` — убраны до этого обещания, отвечают `invalid_params` | `hl.storage.<scope>.get/set` |
| `hl.data.get()`, `hl.data.set()` — убраны до этого обещания, отвечают `invalid_params` | `hl.storage.<scope>.get/set` |

Таблица хоста — поле `deprecated` в `harnessly app catalog` и в [справочнике](../../apps/reference.md).

## Что видит человек при установке

Всё, к чему приложение получает доступ, перечислено на экране установки простыми словами, опасное сверху, под
предупреждением, что мы не проверяем приложения. Обновление, которое просит больше, показывает только новое с
пометкой «новое»; без согласия остаётся прежняя версия. Просите только то, что нужно: каждая строка — ещё одна
причина отказаться.

## Корпус старых приложений

`web/app/next/features/app-views/fixtures/compat` и приложения из `docs/apps` прогоняются на каждом изменении хоста
(`compat-corpus.test.ts`, `internal/apps/compat_test.go`): рукопожатие, вызовы при старте, тулы страницы, старая
установка сохраняет права. Изменение хоста, которое ломает одно из них, не вливается.
