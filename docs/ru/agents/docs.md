# Документация из командной строки

Документация, которую человек читает на странице /help, доступна и вам — через `harnessly docs`. Ей не нужны ни
рантайм, ни сеть: встроенные страницы лежат в бинаре, страницы команды — файлы на машине.

```bash
harnessly docs                         # разделы и их страницы, и где лежат страницы команды
harnessly docs search hub deploy       # страницы со всеми словами, лучшие первыми, со строкой, где нашлось
harnessly docs read self-host/own-docs # напечатать страницу
harnessly docs add runbooks/deploy-api ./deploy-api.md --section-title "Регламенты" --lang ru
```

## Читайте, прежде чем гадать

Когда человек спрашивает, как что-то работает в harnessly, как что-то настроить или как это делается у команды,
сначала поищите в документации, а потом отвечайте по памяти: там лежат собственные страницы команды, и они главнее
ваших догадок.

## Допишите то, чего не хватало

Если вы разобрались в том, чего в документации не было (порядок выката, лечение повторяющейся ошибки, как устроен
сервис команды), предложите это записать. Получив согласие:

```bash
harnessly docs add runbooks/deploy-api --title "Выкат API" --picture ./after-deploy.png <<'MD'
Выкатываем только из main: CI собирает образ, выкат — это мерж в `deploy/prod`.

![Пайплайн после выката](img/after-deploy.png)

## Откат
…
MD
```

- **РАЗДЕЛ/СТРАНИЦА** — латиница в нижнем регистре через дефис: `runbooks/deploy-api`. Новый раздел создаётся с
  `--section-title` (и `--audience people|agents|all`); добавление во встроенный раздел (`start/our-vpn`) сохраняет
  его название. Страница с именем встроенной заменяет её на этой машине.
- Первая строка страницы — её заголовок (`# …`), либо его ставит `--title`.
- **Картинки**: `--picture ФАЙЛ` (png, jpg, gif, webp, svg, до 8 МБ) копируется рядом со страницей как `img/<имя>`;
  показывается так: `![что на ней](img/<имя>)`. Скриншот настоящего экрана лучше его описания.
- **Схемы**: блок `mermaid` рисуется на странице, как в чате. Он лучше картинки со схемой: следующий агент сможет
  его поправить.
- Существующая страница без `--replace` не перезаписывается.
- Страница сразу появляется на /help; `harnessly docs path` покажет, в какую папку она легла.

## Как писать страницу

- Одна страница — один вопрос: «как мы выкатываем API», а не «всё про API».
- Команды, которые можно скопировать и выполнить как есть; что должно получиться после каждой.
- Зачем — одним предложением там, где это неочевидно; без истории, как к этому пришли.
- Ссылки на другие страницы — по их файлам (`../self-host/own-docs.md`), они открываются внутри документации.
