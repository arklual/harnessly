# Стендап

Пример приложения с локальным бэкендом: агент собирает апдейты команды, человек правит и удаляет их в окне. Показывает
то, что нужно любому приложению со своим процессом: доверие `trusted`, stdio MCP-сервер из `.mcp.json`, обмен данными
между агентом и окном через файлы чата, карточку в ленте и правила `agent.tools`, у которых понятные границы.

```text
standup/
  harnessly/app.json        trusted; виды main (панель, во весь экран) и card (в ленте чата)
  .mcp.json                 сервер standup: node ${CLAUDE_PLUGIN_ROOT}/backend/server.mjs
  backend/                  server.mjs (stdio MCP), store.mjs (файл дня), server.test.mjs (node --test)
  ui/                       index.html + main.js (окно), card.html + card.js (карточка), style.css
  instructions.md, skills/run-standup, commands/standup.md
  evals/, fixtures/         сценарии для `harnessly app eval` и мок сервера standup
  remote-server-example/    тот же набор инструментов по Streamable HTTP: единственный сервер, который доступен виду
```

```sh
harnessly app validate docs/apps/standup --strict
(cd docs/apps/standup && node --test)       # тесты бэкенда
harnessly app dev docs/apps/standup
harnessly app enable harnessly.standup       # в чате, где нужен стендап; затем /harnessly-standup:standup
```

## Как устроено

- **Данные.** Записи дня лежат в `standup/<ГГГГ-ММ-ДД>.json` в папке чата. Сервер Claude Code запускает сам (по `.mcp.json`),
  его рабочая папка и есть папка чата, а `${CLAUDE_PLUGIN_ROOT}` раскрывается в папку пакета. Окно читает и пишет тот же файл
  через `hl.files` (права `files.read:standup/*.json`, `files.write:standup/*.json`). Дата дня считается по местному времени
  машины и браузера: на одной машине они совпадают.
- **Окно к серверу не ходит.** `hl.tools.call` вызывает только удалённый сервер по `https://` на публичном адресе, не stdio и не
  localhost. Поэтому окно работает с файлом, а не с инструментами. Если бэкенд нужен окну, он живёт отдельно по https (см.
  `remote-server-example/server.mjs`), а `.mcp.json` называет его адрес.
- **Правка.** Окно перечитывает файл перед каждой записью, чтобы не затереть то, что агент сохранил секунду назад, пишет запись
  с `updatedBy: "person"` и после успеха шлёт агенту `hl.chat.send`. Запись при ошибке не меняется на экране (pessimistic).
  Окно и сервер не блокируют друг друга: если оба пишут в одну долю секунды, выигрывает последний.
- **Удаление.** У агента нет инструмента, который удаляет. Человек жмёт «Удалить», `hl.ui.confirm` возвращает `true` или `false`,
  и только тогда запись уходит из файла.
- **Карточка.** `show_standup` отвечает видом `ui://harnessly.standup/card`. Лента читает результат инструмента из расшифровки
  агента, а там это первая строка текста, обрезанная до 100 символов, поэтому текст ответа это одна короткая строка
  `{"_meta":…,"data":{"date":"…"}}`, а записи карточка читает из файла сама. Тест `backend/server.test.mjs` следит за длиной.
- **Тема.** Окно берёт только токены `--t-*` с запасными значениями на время до подключения (светлые и тёмные по системе),
  сверстано от 360 px.

## Что `agent.tools.deny` делает и чего нет

Правила сравниваются с сырой строкой вызова, это не песочница, а ограда от ошибок агента.

- `Edit`, `Write`, `MultiEdit`, `NotebookEdit` перечислены по отдельности: правило `Edit(...)` другие три не покрывает.
- Маска `*/standup/*` стоит со звёздочкой в начале, потому что Claude Code присылает абсолютный путь. Путь без каталога перед
  `standup/` (относительный) под неё не подходит.
- Закрыты `rm`, `unlink`, `mv`, `shred` и `find` с `standup` в строке. Не закрыты `cd standup && rm …`, `sed -i`, перенаправление
  `> standup/…`, скрипты на python и node: правило `Bash(…)` не принимает символ `>`, а строки со скриптами (`python3 -c`)
  охрана переводит в подтверждение человеком, не в отказ.
- `allow` ничего не разрешает: охрана отвечает только отказом или подтверждением, остальное решает режим прав чата. Поэтому
  списка `allow` в манифесте нет.

Настоящая защита от удаления тут одна: у сервера нет такого инструмента.

## Чего в манифесте нет намеренно

`agent.skills`, `agent.mcp`, `chat.commands`, `activation.on`: валидатор их проверяет, но ничего не включают. Claude Code сам
подгружает все `skills/*`, `commands/*.md` и `.mcp.json` пакета, а приложение человек включает в чате сам. `agent.mcp` нужен
только Sinopia.
