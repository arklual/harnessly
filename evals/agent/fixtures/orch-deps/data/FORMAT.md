# Журнал сканера билетов (data/scans.log)

Одна строка — один скан. Два формата вперемешку:

- v1: `время|ворота|билет|результат`, например `1794700037|B|T1012|ok`;
- v2 (каждая пятая строка): JSON `{"v":2,"time":…,"gate":…,"ticket":…,"status":…}`.

Результат: `ok` — сканер пустил, `dup` — сканер сам признал повтор, `bad` — билет недействителен.

Правила отчёта (так считает бухгалтерия площадки, по порядку строк):

1. `bad` — отказ (`rejected`), билет в учёт не идёт;
2. `dup` — повтор на этих воротах (`duplicates`), даже если билет раньше не встречался; такой скан билет «не открывает»;
3. `ok` по билету, который уже прошёл раньше `ok`-сканом на любых воротах, — тоже повтор, считается на воротах этого скана;
4. иначе — вход (`entered`) на этих воротах; билет считается прошедшим.

`unique_tickets` — сколько разных билетов вошли.
