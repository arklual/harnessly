## Формат доски целиком

Доска — один HTML-файл: `<head>` страницы с `support.js`, шаблон в `<x-dc>` и, как правило, скрипт логики. Рантайм
превращает шаблон в React. Ниже описано то, что рантайм делает на самом деле; где он строже, чем кажется, об этом сказано.

```html
<!doctype html>
<html><head>
<meta charset="utf-8">
<script src="./support.js"></script>
</head><body>
<x-dc>
  <helmet>
    <style>.row:hover { background: var(--t-surface-raised); }</style>
  </helmet>
  <main style="padding: 24px; display: flex; flex-direction: column; gap: 12px">
    <h1 style="font-size: 24px; margin: 0">{{ title }}</h1>
    <sc-for list="{{ rows }}" as="row">
      <div class="row" onClick="{{ row.pick }}">{{ $index }}. {{ row.name }}</div>
    </sc-for>
    <sc-if value="{{ empty }}"><p>Пока пусто</p></sc-if>
  </main>
</x-dc>
<script type="text/x-dc" data-dc-script data-props='{"title":{"editor":"text","default":"Гости"}}'>
class Component extends DCLogic {
  state = { picked: null };
  renderVals() {
    const names = ['Анна', 'Борис'];
    return {
      rows: names.map((name) => ({ name, pick: () => this.setState({ picked: name }) })),
      empty: names.length === 0,
    };
  }
}
</script>
</body></html>
```

### Подстановки

`{{ … }}` — не JavaScript. Это путь и больше ничего: `a.b`, `a[1]`, `a.0`, `a["b"]`, литерал (`{{ 12 }}`, `{{ "x" }}`,
`{{ true }}`, `{{ null }}`), перед каждым можно поставить `!` (`{{ !open }}`).

- Всё остальное не вычисляется и даёт пустоту: `{{ n + 1 }}`, `{{ a ? b : c }}`, `{{ this.x }}`, `{{ state.q }}`. В тексте
  консоль скажет `{{ x }} never resolved`. Посчитай в `renderVals()` и дай имя.
- Имена ищутся по порядку: переменные ближайшего `sc-for` (и `$index`), затем то, что вернул `renderVals()`, затем пропсы.
- В тексте `null`, `undefined`, `true` и `false` не показываются; массив или React-элемент вставляется как есть; любое другое
  значение становится `<span class="sc-interp">`. Этот span — элемент: помни о нём для `:first-child` и `gap` во флексе.
- Атрибут целиком (`width="{{ w }}"`, `onClick="{{ pick }}"`) сохраняет тип значения: число, функцию, объект. Смешанный
  (`href="/e/{{ id }}"`) всегда строка, `null` превращается в пустоту.

### Атрибуты

- Пиши как в HTML: `class` и `style` подходят. В `style` могут быть подстановки, в том числе целые объявления:
  `style="display: flex; {{ extra }}"` при `extra: 'display: none'` даст `display: none`; свойство, записанное дважды, остаётся
  на первом месте с последним значением. `style="{{ obj }}"` принимает объект стилей React.
- Атрибут без значения на HTML-элементе (`<input disabled>`, `<video loop>`) означает true.
- События пишутся как в React и принимают функцию: `onClick="{{ pick }}"`. Всё, что не функция, отбрасывается. `on-click`
  работает на `x-import` и `dc-import`, но не на обычных элементах.
- `ref="{{ boxRef }}"` принимает функцию или `React.createRef()`.
- `style-hover`, `style-focus`, `style-active` и подобные содержат объявления для этого состояния:
  `<a style="color: gray" style-hover="color: white">`. Текст берётся буквально, `{{ }}` внутри не работает. Для динамического
  состояния используй класс и правило в `<helmet><style>`.
- `hint-size="320,48"` и `hint-placeholder-…` только описывают заглушку, пока доска пишется, и не попадают на страницу.
  Встретил — не удаляй, на крупные импорты добавляй.

### sc-if и sc-for

```html
<sc-if value="{{ open }}" hint-placeholder-val="{{ false }}"> … </sc-if>
<sc-for list="{{ items }}" as="item" hint-placeholder-count="3"> … {{ item.name }} {{ $index }} … </sc-for>
```

`value` проверяется как в JavaScript: строка `"false"` истинна, поэтому передавай настоящие булевы значения из `renderVals()`,
а не строки. Ветки else нет: пиши второй `sc-if` с `{{ !open }}`. `list` обязан быть массивом, иначе консоль предупредит и
ничего не нарисуется. Дети `sc-for` различаются по позиции: чтобы состояние строки пережило перестановку списка, храни его в
логике по id.

### x-import: компонент из скрипта

```html
<x-import component-from-global-scope="{{kit}}.Button" variant="primary" onClick="{{ save }}" hint-size="120,40">Сохранить</x-import>
<x-import component-from-global-scope="IOSDevice" from="./ios-frame.jsx" dark="{{ true }}"> … </x-import>
```

- `component-from-global-scope` — путь через точку от `window`, может быть подстановкой (`"{{ deviceName }}"`). Рантайм ждёт,
  пока компонент появится, и до этого показывает заглушку.
- `from` — файлы через пробел, которые надо загрузить; `.jsx` проходит через Babel. Они грузятся сразу, как только доска прочитана,
  даже внутри ложного `sc-if`. Файл, который не загрузился, попадает в лог как `FAILED to load`.
- Пропсы из `kebab-case` становятся `camelCase`, кроме `data-*` и `aria-*`; дети передаются как дети. Проп без значения
  приходит пустой строкой: пиши `dark="{{ true }}"`.
- Элемент обёрнут в `<div class="sc-host-x">`. Из его `style` обёртка берёт только width, height, position, top, left, right,
  bottom, inset, z-index и transform; если их нет, у неё `display: contents`. Остальные стили должны быть пропсами, которые
  понимает компонент.

### dc-import: другая доска

```html
<dc-import name="SiteNav" active="events" style="position: relative; z-index: 1" hint-size="100%,64px"></dc-import>
```

`name` — это файл `./SiteNav.dc.html` рядом с доской. Он обёрнут в `<div class="sc-host">`, обёртка и берёт `style`. Его пропсы —
атрибуты (`kebab-case` в `camelCase`); дефолты из его собственного `data-props` здесь **не** действуют, поэтому в логике
учитывай пропуски (`this.props.active ?? 'home'`). Его `<helmet>` попадает на страницу один раз. Вместо отсутствующего файла
будет заглушка, а консоль скажет, какого файла нет.

### helmet

`<helmet>` хранит то, что идёт в `<head>`: `<link>`, `<style>`, `<script>`, `<meta>`. Он копируется как написан, поэтому `{{ }}`
внутри не работает. Элементы идут в порядке записи, но `<script src>` грузится асинхронно: не рассчитывай на него в следующем
скрипте (`x-import` сам дождётся своего компонента). `<link>` с `href` или `<script>` с `src`, которые какой-то helmet уже
поставил, пропускаются, так доски делят шрифт или кит; `./a.css` и `a.css` считаются разными. Две особые формы:

- `<meta name="design_doc_mode" content="canvas">` делает доску холстом, с нейтральным фоном холста за ней.
- `<helmet data-dc-atomics>` добавляет короткие служебные классы (`.ac`, `.fs12`, `.col`…), которыми пользуются некоторые
  сгенерированные доски.

### Логика: DCLogic

Скрипт — это класс `Component extends DCLogic`, компилируется один раз на правку. `React` и `ReactDOM` доступны.

| Член | Что делает |
| --- | --- |
| `this.props` | дефолты `data-props` с наложенными текущими настройками или атрибуты `dc-import` |
| `this.state`, `setState(objectOrFn, done)` | как в React; начальное состояние объявляй полем класса |
| `forceUpdate()` | перерисовать (без колбэка) |
| `renderVals()` | вызывается при каждой отрисовке, возвращает имена для `{{ }}`: значения, объекты, функции |
| `componentDidMount()` | после первой отрисовки: таймеры, слушатели, замеры |
| `componentDidUpdate(prevProps)` | после каждой следующей; второго аргумента нет, состояние сравнивай сам |
| `componentWillUnmount()` | убрать то, что запустил `componentDidMount` |

Что из этого следует:

- `renderVals()` вызывается часто: без `setState` и без тяжёлой работы. Обработчики создавай там же стрелочными функциями.
- Исключение в `renderVals()` не ломает страницу: доска рисует плашку `<имя>.renderVals(): <сообщение>`, а ошибки в консоли нет,
  поэтому смотри на скриншот.
- Правка логики перезапускает доску: состояние сбрасывается, `componentDidMount` вызывается снова. Правка шаблона состояние
  сохраняет.
- Доска без скрипта допустима; тогда в `{{ }}` доступны только её пропсы.

### data-props: настройки и размер превью

`data-props` у скрипта логики — JSON, по записи на проп. Человек видит записи в панели и меняет их на лету.

```json
{
  "variant": { "editor": "enum", "options": ["Desktop", "Mobile"], "default": "Desktop", "section": "Экран" },
  "loading": { "editor": "boolean", "default": false, "section": "Состояния" },
  "gap": { "editor": "range", "default": 12, "min": 0, "max": 48, "step": 4, "unit": "px" },
  "accent": { "editor": "color", "options": ["#3b82f6", "#2fbf6c"], "default": "#3b82f6" },
  "title": { "editor": "text", "default": "" },
  "$preview": { "width": 438, "height": 900 }
}
```

`$preview` — не проп: он фиксирует рамку доски. Без него доска заполняет окно. Внутри HTML-атрибута кавычки становятся `&quot;`,
либо возьми атрибут в одинарные кавычки.

### Как рисовать хорошую доску

- Сначала скажи, о чём доска: реальный сценарий и его состояния (загрузка, пусто, ошибка) переключателями в `data-props`, а не
  лишними копиями доски. Содержимое правдоподобное и про этот продукт, не lorem ipsum.
- Раскладка живёт в `style`, чтобы её правила панель свойств. `<helmet><style>` — для того, что `style` не выразит: цепочки
  `:hover`, медиа- и контейнерные запросы, ключевые кадры, многократно повторённые классы.
- Цвета, отступы и шрифты берутся из токенов дизайн-системы (их называет README в `_ds/`). Жёстко заданное значение не будет
  следовать теме. Тема переключается на `<html>` из `componentDidMount` и `componentDidUpdate`, как у соседних досок.
- Если у экрана два размера, проверь оба: одна доска с настройкой `variant` или правилами `@container`, а не две почти копии.
- Длинные списки идут из `renderVals()` через `sc-for`, а не вставленной разметкой. Доска, которая рисуется дольше нескольких
  секунд, слишком тяжёлая: сократи список.
- Логика остаётся маленькой. Правилам настоящего продукта здесь не место; важно то, что видит человек.

### Как работать с компонентами дизайн-системы

- Прежде чем рисовать, поищи в ките: `{{kit}}` на `window`, документация в `project/_ds/*/README.md`. Настоящий компонент
  выглядит правильно в любой теме и показывает то, что продукт получит на самом деле.
- Подключай кит в `<helmet>`: сначала его стили, потом скрипт, как в соседней доске. Киту, которому нужен React, хватает копии
  рантайма: свою не добавляй.
- Передавай документированные пропсы компонента и ничего больше. Имена пропсов копируй из README: неверное имя молча не сработает.
  Булевы значения и числа — это `{{ true }}` и `{{ 12 }}`, потому что `size="12"` — строка.
- Если такого компонента в ките нет, собери его из меньших и токенов и скажи об этом в ответе: возможно, он нужен в дизайн-системе.
  Не перекрашивай внутренности компонента кита селекторами.
- Компонент, который вечно показывает заглушку, указан неверным путём: проверь в консоли через `window.{{kit}}`.
