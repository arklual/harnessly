# Видео: другие движки

`tkVideo.register` ставит что угодно на время сцены, и движки смешиваются в одной сцене. Выбирай по сцене: 2D-хореография — GSAP
(`{{cli}} design video guide motion`), частицы и свет — canvas или шейдер, объём — 3D, много сталкивающихся тел — физика.

```js
tkVideo.register({
  name: 'particles',
  ready: function () { return loadWhatItNeeds(); },   // необязательно: сцена ждёт этот промис
  seek: function (ms) { draw(ms / 1000); },           // рисует момент ms; false значит, что ничего не изменилось
});
```

Движок рисует только от времени, без часов и без памяти о прошлом кадре: `seek` зовут в любом порядке, в том числе назад.

- **Canvas 2D.** Рисуй весь кадр в `seek`. Частица — формула от времени и её зерна (`x = x0 + vx * t`), а не значение, сдвигаемое каждый кадр.
- **WebGL и шейдеры.** Передавай `u_time` в шейдер и рисуй в `seek`. Контекст создавай с `preserveDrawingBuffer: true`, иначе в снимок попадёт пустой
  кадр. GPU на машине нет, кадр считает процессор: держи шейдер простым и сначала замерь один кадр.
- **3D, Lottie и библиотеки физики** пока не в ките. Нужный файл положи в проект и грузи оттуда, только если человек попросил, и предупреди, что
  рендер может быть медленным. Физика: посчитай позы один раз фиксированным шагом в `ready`, сложи в таблицу, а `seek` пусть читает таблицу.
- GSAP может вести числа любого движка: твин `state.u_mix` внутри `tkVideo.motion`, а `seek` его читает.
- Движок не ходит в сеть: проверка падает на любом внешнем адресе.
