# Видео: запись интерфейса продукта

Для просьбы «запиши демо»: настоящий интерфейс сайта, снятый по сценарию действий, с нарисованным курсором, камерой, которая едет к кликам, и
окном браузера, всё это накладывается в сцене. Не пересобирай интерфейс в HTML и не снимай экран.

## 1. Сценарий и запись

```yaml
# demo.yaml
name: demo                      # records/demo.mp4 и records/demo.json
url: https://app.example.com/login
viewport: {width: 1920, height: 1080}   # размер страницы в CSS-пикселях (по умолчанию)
scale: 2                        # 3840x2160 для видео 1080p: камера может увеличить вдвое, текст останется чётким
theme: light                    # light | dark
steps:
  - {do: type, into: "input[name=email]", text: "ann@example.com"}
  - {do: type, into: "input[type=password]", secret: DEMO_PASSWORD}   # значения в сценарии нет
  - {do: click, on: "text=Войти"}
  - {do: wait-for, on: "text=Проекты", timeout: 20000}
  - {do: click, on: "text=Новый проект", pause: 400}
  - {do: type, into: "#name", text: "Весенний запуск"}
  - {do: key, key: Enter}
  - {do: scroll, by: 700, ms: 900}
  - {do: wait, ms: 1200}
```

Действия: `open url`, `click on`, `hover on`, `type into + text|secret`, `key`, `scroll by|to (+ ms)`, `wait ms`, `wait-for on (+ timeout)`; у любого шага
может быть `pause` (мс покоя после него). Цель — CSS-селектор или `text=Слова` (самый мелкий видимый элемент с этими словами; `text=/regexp/i`
тоже). Для кнопок и ссылок лучше `text=`: он переживает смену вёрстки. Курсор идёт к цели по дуге в темпе человека, страница видит каждое
движение (hover работает), текст набирается со скоростью человека.

```
{{cli}} design video record <project> demo.yaml           # → <project>/records/demo.mp4 + demo.json
{{cli}} secret run --env DEMO_PASSWORD=<имя в сейфе> -- {{cli}} design video record <project> demo.yaml
```

- Страница идёт по своим часам: кадр — это 1/30 с времени страницы, как бы медленно ни считала машина, поэтому анимации плавные и кадры не
  теряются (`dropped` в ответе — кадры без новой картинки, должно быть 0). Цена: примерно 0,2–0,5 с работы на кадр, ролик в минуту снимается
  6–15 минут. Снимай коротко, один раз, запускай в фоне (`run_in_background`).
- Нужны `chrome-headless-shell` и `ffmpeg`. Если их нет, команда скажет, как поставить.
- Первый `open` (или `url`) в ролик не попадает: ролик начинается, когда страница загрузилась. Следующие `open` вырезаются так же.
- Таймеры страницы (`setTimeout`, опросы) идут по часам страницы: спиннер «на 3 с» ждёт 3 с ролика. Запрос к серверу идёт по-настоящему, но в ролике
  занимает кадр-два: перед следующим кликом ставь `wait-for`, а `wait` — там, где человек бы присмотрелся.
- **Секреты.** Пароль вводится только `secret: ИМЯ_ПЕРЕМЕННОЙ` в поле пароля; значение берётся из окружения процесса (запускай через
  `harnessly secret run`), не из файла. Команда отказывается вводить `text` в поле пароля и `secret` в любое другое поле (оно окажется на
  экране). В журнале стоит `••••••••`, а проверка останавливает запись, если значение туда попало. Не записывай страницу, на которой секрет виден.
- Журнал (`demo.json`) перечисляет события по порядку: `open`, `click`, `hover`, `type`, `key`, `scroll`, у каждого время в мс ролика, место курсора и
  рамка элемента. `durMs` — длина ролика: по ней задай длину сцены (`{{cli}} design video scene set ... --dur`).

## 2. Сцена

```html
<script src="/__lib/motion/screen.js"></script>
<main data-transition="fade"><div id="demo" style="width:100vw;height:100vh"></div></main>
<script>
tkScreen(document.getElementById('demo'), {
  src: 'records/demo.mp4', log: 'records/demo.json',
  at: 0.4,              // секунда сцены, с которой идёт ролик
  zoom: 1.7,            // насколько близко камера подъезжает к клику и вводу
});
</script>
```

`tkScreen` рисует окно (панель, адрес, тень, скругления), ролик покадрово (одно и то же время — один и тот же кадр, в плеере и в рендере), курсор по
записанному пути с кольцом на каждом клике и камеру. Всё — функция времени сцены. GSAP не нужен; если `tk.js` подключён после `screen.js`,
пиши `tkScreen`, а не `tk.screen`.

Правка без пересъёмки (всё в параметрах):

- **Время:** `speed: 1.5`, `trim: [2, 41]` (оставленные секунды ролика), `cuts: [[8, 14.5]]` (вырезанные секунды ролика: ожидание, которое не стоит
  показывать). Длина сцены тогда `await tkScreen.duration('records/demo.json', {speed, trim, cuts})` секунд.
- **Камера:** по умолчанию автоматическая (едет к каждому клику и вводу, стоит, возвращается). `zoom`, `lead` (за сколько секунд до клика
  начинает), `hold`, `skip: [0, 3]` (клики, наведения и ввод, номера с 0 в порядке журнала) для тех, что она пропускает, `camera: false` — без камеры. Вручную:
  `camera: [{at: 3, x: 960, y: 400, zoom: 1.8, dur: 1}, {at: 7}]` (секунды сцены, координаты страницы из `bbox` журнала; без `x`/`y` — снова вся страница).
- **Вид:** `frame: 'none'` (ролик на весь блок, без окна), `chrome: 'dark'`, `url: false` или `url: 'example.com/app'` (текст вместо адреса; по умолчанию записанный адрес без порта), `pad: 4`, `cursor: false`, `size: 1.2`, `hand: true`,
  `ring: false`, `intro: false`.
- **Надписи и подписи** кладутся в сцене отдельным слоем поверх окна (блок с `data-build-in` или GSAP), а не в записываемую страницу. Они остаются
  редактируемыми и ходят по времени сцены.

## 3. Правила качества

1. Для видео 1080p снимай с `scale: 2` (`scale: 3` — только для 4K); значение по умолчанию верное. Страница в 1x мылится при наезде камеры.
2. Наезд 1,5–1,8. Больше 2 текст только крупнее, но не чётче. Камера должна доехать до клика раньше курсора и возвращаться без спешки.
3. Смотри на результат, а не верь журналу: `{{cli}} design video frame <project> <scene> --strip 0:12:1s` и кадр в самом близком наезде. Мелкий
   текст читается, окно ничего не обрезает, курсор не закрывает то, куда кликают.
4. Пауза 300–500 мс после клика даёт странице ответить на экране. Долгую загрузку вырезай через `cuts`, а не показывай.
5. Не снимай то, чего человек не видел на настоящей учётной записи: тестовый аккаунт и тестовые данные, и ничего не прячь правкой ролика.
6. Одна запись — много сцен: сцена может взять тот же ролик с другим `trim`, `at` и камерой.
